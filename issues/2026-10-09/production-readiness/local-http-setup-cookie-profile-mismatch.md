# Explicit local HTTP origin and setup-cookie profile disagree

Status: OPEN. Observed on clean 0.4.687 after a requested envplane.local domain switch.

Approved workaround applied 2026-10-09: clean installation explicitly uses ENVPLANE_OAUTH_COOKIE_SECURE=false alongside its local HTTP opt-in, with successful rollout. Browser normal setup navigation reports Ready to configure and successful local auto-claim. No credentials read/submitted and no API auth bypass. The earlier filled tab was no longer present when inspected after session renewal; a fresh setup tab was opened for the operator. Authenticated Enable authentication submission is still pending user completion. Keep the chart/config coherence defect open for a permanent tested fix; this workaround is not a production TLS policy.

Browser setup page shows revision 0, valid callback http://envplane.local/auth/github/callback, and user-reported/visibly reproduced invalid api token after Enable authentication. No credentials were read or submitted by the agent. Initial local auto-claim previously reported success.

Confirmed configuration mismatch: deployed ENVPLANE_PUBLIC_URL_ALLOW_HTTP_LOCAL_DEVELOPMENT=true and PUBLIC_URL=http://envplane.local, but no explicit ENVPLANE_OAUTH_COOKIE_SECURE. Config defaults that flag to true. The chart derives false only when its own ingress.enabled && !ingress.tls.enabled && allowInsecureLocalDevelopment, not when an external relay fronts a declared local HTTP origin. Setup cookies use that flag. A Secure cookie is not usable over plain HTTP on envplane.local (unlike browser localhost exceptions). Without a valid setup session, the old domain session cannot authenticate against the clean installation, leading to invalid api token. Actual blocked-cookie network diagnostics were not captured; the source/config mismatch and visible error are confirmed.

Implementation prompt for Codex: make explicit local HTTP public-origin validation and session/setup cookie configuration coherent. Preserve secure-by-default HTTPS and reject insecure cookie profiles on external origins. Cover .local plus localhost behind external ingress/relay with browser tests: auto-claim must result in a usable setup session and a valid authorized configuration request without static API tokens. Ensure mismatched profiles fail with a typed actionable prerequisite before setup claims success. Never bypass API auth, CSRF, tenant checks or setup-session expiry, and never log client secrets/cookie values. Test old session cookies on a newly installed instance sharing the same domain. Preserve operator overrides; do not silently weaken production cookie security.

Immediate operator option: explicitly use ENVPLANE_OAUTH_COOKIE_SECURE=false only for the authorized local HTTP test installation, or provide trusted HTTPS and retain Secure=true. Any local adjustment must preserve authentication and require user approval for this security-related setting. Reload would clear the user's in-progress form, so hand off rather than replaying the credential-bearing submission automatically.
